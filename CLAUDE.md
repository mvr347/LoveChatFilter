# LoveChatFilter — notes for Claude Code

## Состояние: авто-модерация и усиление фильтра (сделано 2026-10-30)

Сделано: события `ChatViolationEvent`/`PolitePhraseEvent` для LoveBehaivor, слои обхода мата, слова из игры
(`/lovechatfilteradmin add|remove|list|check`, таблица `custom_words` в `database.db`), безопасные слова, транслит.
Весь конвейер мата живёт в `filters/ProfanityScanner` (без Bukkit, покрыт тестами); `FilterEngine` только вызывает его.

Грабли, на которых уже наступали:

- **Мат ищется подстрокой, без границ слова** (так ловится «похуй»), поэтому невинное слово с запрещённым куском
  получало закрашенные буквы («скрафтить»). Лечится безопасными словами: сообщение режется по ним, и сканер
  видит только остальное. Не пытаться лечить «границами слова» вслепую: сломается «похуй».
- **Опечатки одинаковой дистанции для всех слов** делали «сумку» опечаткой «сука». Допуск зависит от длины слова
  (до 4 букв точное совпадение), `allowedDistance`.
- **Слои обхода не должны быть взаимоисключающими**: «сука и bлять» раньше пропускало вторую часть.
- **Один сломанный regex в `badwords-filter.list` не должен выключать фильтр**: слово пропускается по одному
  с предупреждением.
- **Админская команда не должна фильтроваться своим же фильтром**: слова, которые админ вводит в
  `/lovechatfilteradmin add`, раньше закрашивались `ChatListener.onCommand` ещё до выполнения команды (спасал
  только обход `bypass.badwords` у оп). Теперь своя команда пропускается.
- **Добавление слова не должно сбрасывать кулдауны антиспама**: `rebuildFilters()` пересобирает только фильтры,
  `reloadCache()` (по `reload`) заодно чистит кулдауны.
- Тесты на сервере-заглушке: `MockBukkit` присылает команду в `PlayerCommandPreprocessEvent` БЕЗ ведущего `/`
  (настоящий клиент шлёт с ним); SQLite-драйвер в тестах нужно подключать самим (на сервере его даёт Paper);
  JUnit 6.1.3, иначе MockBukkit падает на `OutputDirectoryCreator`. Собирать онлайн: `mvn test` (офлайн `-o` не
  находит MockBukkit в локальном репозитории).
- **Записи слов в базу идут строго по порядку**: `WordLists` держит свою FIFO-очередь и сбрасывает её под замком
  (`flush()`), потому что асинхронные задачи Bukkit порядка не гарантируют ("добавил, сразу убрал" иначе
  возвращало слово после рестарта). `onDisable` вызывает `flush()` до закрытия базы.
- **Безопасные слова режут сообщение токенами "буквы и цифры"** (`SAFE_TOKEN`), а мат ищется токенами из букв:
  иначе безопасное `дурак123` никогда не совпадало.
- **Замаскированная точка в рекламе проверяется всегда, по остатку после обычной цензуры**, иначе обычный адрес
  в том же сообщении прятал второй, замаскированный.
- **Для других плагинов в API: `isProfane` и `containsAdvertising`** (оба игнорируют права обхода). Подключаются
  рефлексией, как делает LoveTweaks; новые методы API обязаны быть `default`, чтобы старые реализации не ломались.

## Управление из веб-панели LoveWebAdmin (сделано 2026-11-09)

В `LoveChatFilterAPI` добавлены методы по умолчанию для панели: `listWords/addWord/removeWord`, `checkText`, `settings/changeSetting/resetSetting`,
`statistics`. Типы только простые (`Map`, `List`, `String`), чтобы мост в панели работал рефлексией без общих классов; вызывать с главного потока.

- **Настройки из панели не переписывают config.yml**: белый список ключей и диапазонов в `WebSettings`, значения лежат в таблице `setting_overrides`
  и накладываются поверх загруженного конфига (`applyOverrides` после старта и после `reload`). Сброс настройки перечитывает файл и снова накладывает остальное.
  Так не теряются русские комментарии с датами. Новый ключ для панели добавляется ТОЛЬКО в `WebSettings`.
- **Статистика** (`ViolationStats`, таблица `violation_stats`) считает каждое нарушение в `FilterEngine.fireViolation` до проверки `auto-moderation`:
  счёт в панели не зависит от сигналов репутации. Запись в базу - раз в минуту асинхронно и при выключении (`onDisable` сначала ждёт очередь записи настроек, потом сбрасывает счётчики, потом закрывает базу).

## Встроенные безопасные слова (сделано 2026-11-10)

- **Файл `safe-words.txt` внутри jar** (около 6700 слов) объединяется с `badwords-filter.safe-words` из config.yml и словами из игры (`bundled ∪ config ∪ DB`) в `FilterEngine.rebuildFilters`. Новые слова нельзя класть в `config.yml`: у существующих серверов он не обновляется, а при наличии ключа `safe-words` берётся только он. Ничего не пишется ни в конфиг, ни в базу, поэтому админские правки не затираются. Ненужное встроенное слово отключается ключом `badwords-filter.safe-words-disabled`. В списках для админа (`listWords`) встроенные слова не показываются (`listedConfigWords`), но `configWords` знает их, и `add` сообщает о дубликате.
- **Список снят со словаря, а не придуман**: частотный словарь русского языка (100 тысяч слов) прогнан через настоящий `ProfanityScanner` с боевым списком; слова, которые он закрашивает по ошибке, минус настоящие оскорбления (по основам из комментариев боевого списка). Плюс слова на стыках: на «-ло» («дело х...»), на «ох-» («стол охрана»), на «пис-/пес-» («вы писать»).
- **Грабля: безопасные слова не лечат широкие regex.** Боевой список почти целиком из сырых `(?i)...`; несколько выражений ловят невинные куски: `[с$][уу]*[ч]*[к][а@4иу]*` («сука/сучка») это любое «ск» (сказать, москва, русский: 5781 слово из ста тысяч), `д[а@4][уу]*н` любое «дан», `[л][о0а@]*х[а-я]*` любое «лх/лох» (плохо), `[нn][іiи1][щshw]...` «нищ» (днище), `[т][в][а@4][р][ь]*` («утварь»), `[а@4][уу]*т[ии1][с$][т]...` («статистика»). Точные слова покрывают только формы из словаря (например, «сказал» в нём нет). Корень решения это правка самих выражений: `[уу]+` вместо `[уу]*` (обязательная гласная), границы слова `(?<![а-яa-z])` перед `лох`, `нищ`, `тварь`, `(?<![а-я])чмо(?!к)`. С такими правками из ста тысяч слов остаётся около 230 закрашенных (в основном настоящие оскорбления).
- **Дыра префикса `*` закрыта**: запись `скрафт*` ручается только за сам префикс, остаток токена сканируется отдельно (`ProfanityScanner.safeLength`): `скрафтить` чисто, `скрафтхуй` закрашивается. Точные безопасные слова дыры не имели.
- Межсловные срабатывания идут не от компактного слоя (он работает только при простых словах в списке), а от выражений с `\s*` и `[^а-я]*` («л о х», «вы/ты + слово», окончания «ве/вы/ты» в роли «вы/ты»): «дело хорошо», «вы писать». Закрываются безопасными словами с одной из сторон; «ты» и «вы» безопасными делать нельзя: контекстные оскорбления («ты тупой») перестанут работать.
